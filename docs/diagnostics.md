# Diagnostics

Every diagnostic has a stable code. Editors show it next to the message,
and code actions use it to offer fixes. Most checks mirror what melange
itself does when it parses and compiles a configuration, but they point at
the exact key or value instead of reporting one error for the whole file.

The server only reports on melange files: a package configuration (a
top-level `package:` mapping with a `name:`) or a pipeline definition
(anything under a `pipelines/` directory, or YAML whose top-level keys are
all pipeline fields). Other YAML gets no diagnostics.

## Errors: melange would fail

| Code | Meaning | Fix offered |
|---|---|---|
| `yaml-syntax` | The file is not valid YAML. | |
| `unknown-field` | melange's strict decoder rejects the key. | Rename to the closest valid key |
| `melange` | Any other error from `config.ParseConfiguration`, placed on the key it is about. | |
| `unknown-pipeline` | `uses:` names no pipeline in the pipeline directories or melange's built-ins. The message lists where it looked. | Closest pipeline name |
| `invalid-uses` | `uses:` is an absolute path or contains `..`. | |
| `unknown-input` | A `with:` key the pipeline does not declare (`undefined input` in melange). | Closest input name |
| `missing-input` | A required input without a default is not set. | Add the missing inputs |
| `bad-checksum` | `expected-sha256`, `expected-sha512` or `expected-commit` has the wrong length or non-hex characters, including every `data:` value used through `${{range.value}}`. | |
| `step-shape` | A build step has `with:` without `uses:`, or combines `uses:`/`with:` with `runs:`. In test pipelines this is informational. | |
| `undefined-variable` | A `${{...}}` that melange cannot resolve where it is used: unknown `vars.*`, `subpkg.*` outside subpackages, `range.*` outside `range:` subpackages, `inputs.*` outside pipelines, or an expression that is not a single name. In fields melange only substitutes at parse time this is a warning, because the text is kept literally. | Closest variable |
| `variable-not-substituted` | A variable used where melange never substitutes it, such as inside `vars:` values or a step's `environment:`. | |
| `variable-spacing` | `range.*` and `package.description` are only substituted when written exactly, without spaces. | Rewrite without spaces |
| `bad-condition` | `if:` does not parse with melange's condition grammar. | |
| `unknown-linter` | A `checks.disabled` entry that is not a melange linter; the build fails at lint time. | Closest linter |
| `bad-capability` | A `setcap:` capability melange does not allow, or a missing `reason:`. Unknown `CAP_*` names in `needs.capabilities` are warnings. | |
| `subpackage-name` | A subpackage with no name, a duplicate name, the main package's name, or an invalid name. | |
| `package-name` | The package name does not match melange's pattern. | |
| `bad-regex` | A `match:` or `ignore-regex-patterns` entry that is not a valid regular expression. | |
| `bad-value` | A value outside a fixed set, such as `update.schedule.period`, or a non-boolean for a boolean field. | Valid values |
| `melange-compile` | The real `melange compile` failed on something the checks above do not cover, such as shell syntax in `runs:`. It only runs when no other errors are found. | |

## Warnings and information

| Code | Meaning |
|---|---|
| `missing-patch` | A patch named in `patches:` is not in the package's source directory, `./<package-name>/`. Patches with paths, patches in a `working-directory`, and patches generated by a `runs:` step are not checked. |
| `deprecated` | A field melange marks deprecated, such as `update.github.tag-filter` (use `tag-filter-prefix`). Shown struck through. |
| `update-disabled-reason` | `update.enabled: false` without an `exclude-reason:`. |
| `update-schedule-reason` | `update.schedule` without a `reason:`. |
| `agent-note` | An `@agent` note that is empty or whose fence is never closed. See [agent notes](agent-notes.md). |

`update-disabled-reason` and `update-schedule-reason` share wolfictl's rule
names, so a `#nolint:update-disabled-reason` comment silences both tools.

## How the checks were calibrated

`make corpus` runs every feature over a real repository. Against the
Chainguard stereo monorepo (9,448 package files and 472 pipeline files) the
server reports errors or warnings in 8 package files, each a genuine issue:
undefined variables left as literal text in descriptions, an expression
written inside `${{ }}`, a typo'd `${{rane.key}}`, and update schedules
without a reason.
